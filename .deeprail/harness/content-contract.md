# Public Content Contract

Public DeepRail content MUST stand on its own and explain DeepRail through its own problem definition, normative logic, artifacts, evidence, workflows, decision rights, and runtime behavior.

The public repository contains only artifacts required to understand, adopt, operate, validate, and govern DeepRail. Public builds MUST NOT require files outside the repository.

Book, Docs, Standard, Workflows, and Runtime are separate projections with different reader and operator responsibilities.

Runtime-specific product names are permitted only inside real integration surfaces such as adapters or setup instructions. DeepRail Core semantics remain vendor-neutral.
